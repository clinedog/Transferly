# Purpose

Keep documentation accurate, actionable, and aligned with the codebase.

## Trigger conditions

Use for documentation additions, corrections, workflow guides, architecture notes, or release/deployment records.

## Best practices

Derive claims from code and executed commands, link to owners and scripts, distinguish examples from production credentials, and record prerequisites and rollback implications.

## Workflow

1. Identify the audience and source of truth.
2. Inspect related code, scripts, and existing docs.
3. Write concise task-oriented guidance.
4. Validate commands and file references.
5. Update nearby docs when a workflow changed.

## Validation checklist

- Commands, paths, and configuration names are current.
- No secrets, tokens, or private data are included.
- Guidance states required prerequisites and expected outcomes.

## Expected outputs

Accurate documentation changes and a short summary of verified instructions.
