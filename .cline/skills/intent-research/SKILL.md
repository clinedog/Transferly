# Purpose

Turn current primary-source research into an implementation-ready recommendation.

## Trigger conditions

Use for external APIs, changing standards, provider contracts, library choices, or uncertain technical facts.

## Best practices

Start with local references, use official primary sources for unstable facts, separate evidence from inference, and avoid logging or storing credentials while testing providers.

## Workflow

1. Define the decision, constraints, and unknowns.
2. Inspect local adapter code and reference docs.
3. Consult official docs for externally meaningful behavior.
4. Compare options against Transferly architecture and safety needs.
5. State a recommendation, evidence, and open risks.

## Validation checklist

- Claims about external behavior have current primary sources.
- Assumptions and unknowns are explicit.
- Recommendation names affected modules and verification steps.

## Expected outputs

Concise research synthesis, cited evidence, recommendation, and implementation implications.
