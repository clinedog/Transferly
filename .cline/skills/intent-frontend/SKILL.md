# Purpose

Create reusable, accessible, and maintainable user-facing interfaces.

## Trigger conditions

Use for components, pages, styles, client state, forms, navigation, or UI defects.

## Best practices

Reuse existing design primitives, use semantic HTML, keep components small, avoid duplicate state, and design mobile-first with explicit loading, empty, and error states.

## Workflow

1. Inspect the existing component system and closest screen.
2. Define behavior, states, and responsive requirements.
3. Implement reusable composition rather than one-off markup.
4. Check keyboard, focus, contrast, and viewport behavior.
5. Run lint, build, and relevant e2e tests.

## Validation checklist

- No inaccessible interactive element or unlabeled form control.
- Layout works on mobile and desktop without horizontal overflow.
- User-facing errors are understandable and recoverable.

## Expected outputs

Reusable UI changes, accessibility checks, and build/test evidence.
